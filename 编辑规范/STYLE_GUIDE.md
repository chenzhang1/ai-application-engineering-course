# 教材风格指南（每章作者必读必守）

## A. 章节模板

每章 Markdown 按以下顺序组织（小节可合并，但不可缺失）：

```
# 第 N 章 标题
> 本章目标 / 前置知识 / 学完你能做什么（3 个要点）
## N.1 真实问题引入（Java 工程师视角的一个具体场景）
## N.2 一句话解释 + 生活类比 + 类比边界（"哪里像、哪里不像"必须有）
## N.3 正式原理与准确术语（新术语：中文（英文）+ 一句定义 + 例子）
## N.4 最小完整示例（EX 编号，真实运行输出）
## N.5 逐段解释（关键代码段）
## N.6 安装/文件位置/运行命令（三件套必须给全）
## N.7 常见错误与排查（≥3 个真实报错样例：报错信息→原因→修复）
## N.8 企业场景中的使用方式（Spring Boot 集成视角）
## N.9 练习（基础 2 + 代码 2 + 调试题 1）与参考答案（答案放章末折叠区）
## N.10 自测检查表（5-8 条"我能……"句式）
## N.11 面试追问（2-4 个，标注[模拟题]）
```

## B. 示例编号与文件规则

- 全书示例唯一编号：`EX-<两位章号>-<两位序号>`，如 EX-02-03。
- 每个可运行示例必须同时落盘：`示例代码/ch<N>_<slug>/ex_NN_XX_<name>.py`，文件内首行注释含编号与运行命令。
- 教材中代码块上方必须标注：`EX-02-03 | 示例代码/ch02_basics/ex_02_03_copy.py`。
- 完整可运行 / 节选 / 伪代码 三类必须显式标注，禁止"此处略"。
- 输出块规则：确定性程序→贴真实运行输出（必须真的跑过）；模型相关→标 `# 示例输出（非真实记录）` 或 `# Mock 运行输出`。

## C. 代码标准

- Python 3.10+ 语法；类型注解全量；f-string；pathlib；logging 非 print（示例可用 print 说明，工程代码用 logging）。
- 所有示例文件：无硬编码密钥（一律 `os.environ.get("OPENAI_API_KEY")`，缺失则明确报错提示）。
- LLM 相关示例统一双模式：`MODE=mock`（默认，不联网）与 `MODE=real`（需 Key）。统一用 `示例代码/公共/llm_client.py`（由第四部分作者创建，其余作者 import 使用，不得各写一套）。
- 示例间目录相对独立，每个目录可单独运行；公共依赖只允许标准库 + requirements.txt 内的包。

## D. 验证义务（不做完不许交）

1. 每个示例实际运行一次；输出贴进教材（模型示例用 Mock 输出）。
2. 每章至少 3 个 pytest 测试进 `测试/test_ch<N>.py`（覆盖：正常/边界/非法输入）。
3. 运行记录写入 `验证报告/运行日志/part<N>.md`：命令、退出码、输出摘要、失败与修复过程。
4. 交回报告必须含：文件清单、EX 编号清单、测试结果（pytest 摘要行）、未验证项。

## E. 语言与排版

- 全中文；专有名词首现给"中文（English）"；代码注释中文。
- Markdown：`##` 编号小节；表格宽度 ≤5 列；代码块标语言。
- 长度硬指标：正文密度优先，禁止目录式空话；每章字数见 syllabus 的"规模"列。
- 练习答案统一放章末 `### 参考答案` 下，题干处不泄漏。
- 提示块用引用语法：`> ⚠️ 常见坑：`、`> 💡 类比边界：`、`> 📌 生产提示：`。

## F. 禁止事项

- 不出现"篇幅有限，此处从略""读者自行实现"。
- 不虚构版本号、性能数据、公司案例（可用"某电商平台（合成案例）"）。
- 不混用不同库版本的导入路径；历史写法必须标注适用版本与替代。
- 不把营销文章数据当事实引用。
