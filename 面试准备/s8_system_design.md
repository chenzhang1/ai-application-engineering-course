## 12.8 专题八：系统设计与项目深挖

> 对应正文：全书综合 + 两个项目（综合项目/p1、p2）的"面试讲法"小节 + 第十部分大纲（ch57~ch61，正文交付前引用其编号）。设计题与项目深挖题考的不是知识量而是**决策质量与真实性**——评分者暗中打分的三件事：约束先行（先问需求再画图）、权衡显式（每个选择说得出"放弃了什么"）、诚实边界（不知道就说不确定）。

### 题 8-1 [模拟题] 现场设计：给一家 500 人的公司做一个内部制度知识库

**1. 问题与考查点**：RAG 全链路的工程决策与约束访谈能力——白板题的开场 30 秒（问不问需求）就分出了档次。

**2. 常见错误回答**：上来就画"向量库+LLM"两框图——没有需求访谈（权限模型？更新频率？拒答口径？）、没有评估方案、没有失败路径；或者堆名词（"用向量数据库+Agent+微调"）——每个名词都是风险。

**3. 简洁合格回答**（按白板顺序展开）：
- **先问四个约束**：知识规模与更新频率（几百篇、月更）、权限模型（部门隔离？租户？）、实时性（无）、拒答口径（宁可拒答不编造）。
- **入库管线**：文档源（Markdown/网盘同步）→加载清洗（front-matter 带权限元数据，必需字段缺失拒绝入库）→两级切分（标题分节+节内递归，200/30 量级起步，评估定参）→嵌入入库（记录模型版本，换模型全量重建）。
- **检索**：权限过滤先行（元数据 filter 下推）→向量+BM25 两路（BM25 用现成 ES）→RRF 融合→top-k+阈值（评估集校准）。
- **生成**：编号证据+token 预算装箱（整块丢弃）→结构化输出（answer/citations 分字段）→程序校验引用（失败回退抽取式）→拒答双保险。
- **服务与集成**：FastAPI 暴露 /ask 与 /ask/stream（SSE：meta 引用先行→delta→done）；Spring 侧经网关转发，身份从 JWT 注入，Python 侧不解析消息文本做授权。
- **质量与运维**：评估集（应答+应拒两类）接 CI、结构化日志+trace_id、usage 成本记录、文档同步 webhook、审计留存。

**4. 深入解释**：这张图的每一层都对应 P1 的一个选型决定（README 第 2 节的表格）——面试时可以直接说"这个设计我在一个可复现的项目里完整实现过"，然后引用 25 chunk/16 条评估集/四指标/17 个测试这些锚点。规模演进点主动给：千级 chunk numpy 全量扫描仍可行，十万级换 ANN+过滤下推。成本杠杆：top_k 与 chunk_size 直接乘在输入 token 上、高频 FAQ 可走便宜模型或纯检索直答、拒答与限流拦截无效流量。"先写评估口径再写代码"作为立项纪律收尾——RAG 是概率系统，没有评估口径的项目无法验收。

**5. 工程案例**：P1 全流程（12 篇合成文档→25 chunk→四指标评估→SSE 协议→pytest）就是这道题的可运行参考答案；引用数字时声明"合成语料校准"（题 8-9 的口径纪律）。

**6. 追问与回答边界**：
- 追问 1：为什么不用现成知识库产品？——要点：按需求答——要权限下推+拒答口径+引用协议的定制控制；采购与自建的边界按团队能力与数据敏感级。
- 追问 2：怎么灰度上线？——要点：影子索引+评估对比→按部门灰度→全量；指标回退即回滚（切分参数属索引 schema 级变更）。
- 边界：多模态（图表）解析、OCR 本书只给流程未实测（ch31 待核实项），引用时声明。

### 题 8-2 [模拟题] 现场设计：一个"日志排障 Agent"——能查证据、下结论，高风险动作要人批

**1. 问题与考查点**：Agent+安全+持久化的综合设计——P2 的完整复刻能力；考你把"自主性"关进笼子的设计功力。

**2. 常见错误回答**：设计成"给模型一个能执行任意命令的工具"——权限灾难；或者没有"证据不足怎么办"的设计（模型编个根因就是事故）；或者忘了"人批完进程重启了怎么办"。

**3. 简洁合格回答**：
- **主干 Workflow 化**（路径可画，Q1=能）：解析日志→规则预筛→取证计划→受限只读查询→模型假设（结构化 schema）→证据评估→（有高风险动作时）人工审批→分级结论（P1/P2/UNKNOWN）。
- **工具侧**：白名单三道校验（工具名→参数名→参数值）、SQLite 只读双保险（`mode=ro`+`PRAGMA query_only=ON`）、SQL 全参数化、每次调用写 JSONL 审计（who/when/what/args/result）。
- **模型边界**：只做结构化假设与置信度表达；不给执行权；日志文本截断并包在"证据摘要"数据段（注入边界）——模型可以错、可以被注入，但权限边界在白名单+只读连接+审批门上。
- **拒答**：证据不足→UNKNOWN+指名道姓的缺口清单（缺状态/缺事件/缺依赖记录），不编结论。
- **审批与幂等**：interrupt+Command(resume)，副作用走幂等账本（action_key 唯一），拒绝也是一等结果。
- **持久化**：checkpointer+thread_id=事件单号，跨进程可恢复；结论、证据、审计全部留痕可回放。

**4. 深入解释**：为什么主干不用自由 Agent——可测试性（每节点纯函数）、审计（节点是天然切面）、成本可控（模型只看压缩后的证据摘要而不是全量日志）；这是三问法 Q1/Q3 的直接应用。面试时最有力的收尾："这个系统的 14 个测试里有 10 个在测失败路径——排障工具自己必须先可信。"扩展路径（接 ES/Loki、多轮取证循环、并行取证）说明设计留了口。

**5. 工程案例**：P2 的架构图（README 第 2 节）、失败路径表（第 7 节，每条都有测试锁定）、resume_demo 三段演示（进程内拒绝/跨进程批准/幂等重放）——后者是"恢复语义"的现场讲材，面试官若追问"重启了怎么办"，直接演示。

**6. 追问与回答边界**：
- 追问 1：日志里有敏感信息怎么办？——要点：入库前脱敏、审计分级、检查点按敏感数据管权限（ch47.8）。
- 追问 2：误报率高怎么办？——要点：预筛规则进回归集、置信度校准、把"证据缺口"反馈给日志采集侧——排障工具的错误也是数据。
- 边界：真实日志源（ES/Loki）接入本书未实现，属扩展方向；合成日志数据要声明（题 8-6）。

### 题 8-3 [模拟题] 成本估算题：这个 RAG 问答功能每月花多少钱？

**1. 问题与考查点**：估算框架与杠杆意识——数字可以不知道，**算式与假设必须当场搭**；考你能不能把成本拆到"可操作的杠杆"上。

**2. 常见错误回答**："没数据算不了。"——放弃；或拍一个"大概几千块"——没有算式没有假设，追问一句就塌。

**3. 简洁合格回答**（给算式）：**月成本 = 日请求量 × 每请求成本 × 30**。每请求成本 = embedding 1 次（问题文本，几十 token）+ LLM 1 次（system+top_k 个 chunk+问题 ≈ 输入 token；输出上限受 max_tokens 控制）。P1 的结构给参考量级：编号证据 prompt 约 1~2k token 输入（README 第 7 节）。然后给杠杆与敏感性：① top_k 与 chunk_size 直接乘在输入 token 上（最大的两个杠杆）；② 历史管理——多轮滚雪球，20 轮会话的平均费用可达 5 轮的数倍量级（ch27 口径）；③ 缓存——高频 FAQ 命中缓存跳过生成；④ 模型分级——高频/简单走小模型；⑤ 拒答与限流拦截无效流量。最后声明纪律：**单价以厂商文档当期价为准，本书不背具体价格；给的是量级+敏感性+杠杆**。

**4. 深入解释**：固定成本别漏：入库 embedding（一次性）、评估集夜间回归（持续、有成本）、坏例人工复核（人力成本）。成本要可观测才有估算闭环：每请求 usage 落结构化日志、按租户/功能分桶（ch60 方向）。把成本估算接到"预算护栏"：并发限制（题 2-4）+步数上限（题 6-6）让**成本上限变成配置项**——这句是把成本题升级成架构题的钩子。

**5. 工程案例**：P1 README 第 7 节的单请求成本结构；EX-30-02 的 token 算术（277 vs 187 的对照算法）；EX-34-01 的预算装箱（预算不足时按分数整块丢弃——预算本身就是设计输入）。

**6. 追问与回答边界**：
- 追问 1：请求量翻 10 倍怎么办？——要点：先看缓存命中率、再压 top_k/换小模型、最后扩并发配额——按"边际成本从低到高"排。
- 追问 2：怎么向财务证明成本合理？——要点："每次回答成本 vs 人工答疑成本"折算，附假设清单；不承诺节省比例，给可复核的算式。
- 边界：任何价格类数字现场声明"以厂商当期文档为准"——不背价格是纪律不是心虚。

### 题 8-4 [模拟题] 安全评审题：这个"能查库、能发工单"的 AI 助手，上线前你要拦下什么？

**1. 问题与考查点**：安全清单化能力与纵深防御——考"清单思维"（评审要可执行）与"提示词不是权限控制"这条红线的肌肉记忆。

**2. 常见错误回答**："加个提示词，让它别乱来。"——ch28 红线；或只答某一层（"要做好鉴权"）——没有纵深，单层失守即失守。

**3. 简洁合格回答**（按清单走）：
- **身份与权限**：用户身份只来自请求上下文（JWT/Session），绝不来自问题文本或模型输出；每个工具函数体内第一行校验权限；多租户过滤在检索层。
- **注入防线**：指令数据分离（数据段标记）、输出白名单、**间接注入**意识（库里的工单/网页内容也是不可信输入）；真正的闸门在程序侧。
- **工具面**：只读优先、白名单三道校验、写操作（发工单）必须 interrupt 审批+幂等键、每个工具独立超时。
- **数据面**：脱敏入库、密钥走环境变量/密管（零硬编码）、检查点与审计按敏感数据管权限、只读 DB 账户+参数化 SQL。
- **失效语义**：判定器/权限组件故障 **fail-closed**（拒绝服务优于越权放行）；审计完整可回放（who/when/what/args/result）。
- **红线测试**：越权参数被拒、注入诱导被白名单拦、人工拒绝后不执行——三条都必须有自动化测试锁定（P2 的 test_whitelist_* 与 test_human_rejection_blocks_side_effect）。

**4. 深入解释**：纵深防御的层次感：模型层不可信（可以错、可以被注入）→程序层全闸门（白名单/只读/审批/幂等）→审计兜底回溯（事后可查"谁批的、执行了什么"）。整个方案的题眼一句话："**模型可以错，但拿不到执行权。**"与 Java 团队的分工：权限源与审计流水在 Java 侧 RBAC，Python 侧消费——你是消费者不是权威源，这个边界要主动说。

**5. 工程案例**：P2 README 第 9 节安全设计五条可整体引用；ch28 的注入三层缓解与边界（SQL 有词法边界、Prompt 没有——所以程序侧防线不可省）；P1 的"身份绝不来自问题文本"（README 第 7 节）。

**6. 追问与回答边界**：
- 追问 1：审批人被骗批了怎么办？——要点：审批单载荷带"模型依据的证据摘要"+动作影响说明，人审的是证据不是措辞；高危动作灰度放量。
- 追问 2：审计日志会被注入污染吗？——要点：审计是程序写不是模型写，字段白名单+只追加存储。
- 边界：沙箱内未做渗透测试；清单是评审框架，具体阈值按公司安全规范——把"这份清单要过贵司安全团队"说出口是加分项。

### 题 8-5 [模拟题] 讲一个你做过的 AI 项目（背景与决策）

**1. 问题与考查点**：STAR 变体——本书改成五段：**背景→决策→替代方案→验证→复盘**（普通 STAR 的 R 拆成三段，因为面试官真正要追问的是决策与验证）；考表达的层次感与可验证锚点密度。

**2. 常见错误回答**：按时间流水账讲（"首先我做 A 然后做 B"）——没有决策点；或全是大词（"架构设计""赋能""闭环"）没有一处可验证细节；或者把教学项目包装成生产项目——被追问细节时崩塌。

**3. 简洁合格回答**（以 P1 为例的 90 秒五段讲法）：
- **背景**：内部制度散落、人工答疑耗时；要求答案可溯源、证据不足宁可拒答、按部门隔离。
- **决策**：选 RAG 而非微调/长上下文（四连问：会改/要权限/量大/不实时——三条命中）；检索自实现余弦+词面补偿（当时 embedding 为 mock 的边界决定的补偿设计）；拒答双闸（阈值拦"不自信"、判定拦"自信跑题"）。
- **替代方案**：直接上向量库产品——25 块规模不需要，运维面反而大；只做阈值单闸——实测有"自信跑题"漏网（跨租户案例），所以加了 gate2。
- **验证**：自建 16 条评估集（14 应答+2 应拒）、四指标回归接 pytest（17 个测试）、11 组 curl 实测含权限拒绝与跨租户案例（run log 留痕）。
- **复盘**：阈值与权重只对本语料有效；真实模型路径未实调（沙箱无 Key）——下一步是 CI 夜间真模型回归。
- （然后主动声明：这是教学工程、语料为合成数据。如果面试官问的是商业项目，这个结构原样适用，数据换成真实的。）

**4. 深入解释**：五段里"替代方案"与"复盘"最值钱——它们证明你做过权衡、能自我批评；每段都要有**可验证锚点**（文件名/测试名/数字/运行记录），锚点密度决定可信度。时长控制：先给 90 秒版，面试官要哪个细节再展开哪段——把六段式（题前训练）与五段式（项目叙事）分开用。

**5. 工程案例**：P1 README 第 10 节的 90 秒讲法（可直接背的结构）；P2 README 第 11 节的三问三答（为什么 LangGraph/恢复不重复/模型边界）——两份现成讲材。

**6. 追问与回答边界**：
- 面试官任意细节追问的应对 → 题 8-6。
- 边界：模板不编造经历——你跑过哪个项目就讲哪个；讲不出的细节不要现编（题 8-6 的纪律）。

### 题 8-6 [模拟题] "这个模块具体是你写的吗？为什么这么设计？"——真实性追问怎么接？

**1. 问题与考查点**：12.0.3 说的"第三类最容易被编造的经历击穿"——考真实性与深入度的一致性；这是全卷对"诚信"权重最高的一题。

**2. 常见错误回答**：细节含糊（"大概是用了个框架"）、数字越问越大、被质疑时慌忙改口——**一致性崩塌比"不知道"致命得多**；或者反向过度防御（每个问题都觉得被冒犯）。

**3. 简洁合格回答**：三条纪律：① **具体到可指认**——"拒答双闸在 kb.py 的 answer 函数里，gate1 阈值 0.16 是评估集上应答最低分 0.194 与应拒最高分 0.129 之间取的"；② **知道边界**——"P1 的 LLM 生成路径按 openai 3.35.1 签名实现，但沙箱没有 Key 没有实调过，这一点 README 的未验证项写了"；③ **一致地"不知道"**——没做过的环节直说没做过，然后讲你会怎么做。被质疑时的四步公式：复述对方的质疑点 → 给出当时的约束 → 给出现有证据 → 承认局限。绝不现场改故事。

**4. 深入解释**：为什么诚实边界反而加分——面试官对 AI 项目经历的真伪高度敏感（编造重灾区），"知道自己的项目哪里没验证过"恰恰是**做过的人的标志**——没做过的人没有"未验证项"可讲。替代方案问答模板："当时还考虑过 X，没选它是因为 Y（约束/成本/评估数据），如果 Z 变了我会重评。"把教学项目讲出价值的方法：强调可复现性（同输入同输出、全测试覆盖、运行记录）与迁移点（哪些简化在生产要换）——"每个简化都是显式记录的迁移点，面试时主动说出来比被问出来好"（ch36.5 原话）。

**5. 工程案例**：P1 README 第 12 节"未验证项（诚实清单）"就是面试里"承认边界"的现成话术库（4 条，条条具体）；P2 README 第 11 节对三连问的标准答案。

**6. 追问与回答边界**：
- 追问 1：面试官说"这数字不对吧"？——要点：回到口径（题 8-9 的三句话公式），不慌不改。
- 追问 2：完全没做过的追问（如"你们怎么做 A/B"）？——要点："这个我没做过。我的理解是……但我不装懂。"——理解可以给，经历不能编。
- 边界：本题全部技巧以"你真的做过"为前提——技巧不能替代经历，这是本部分的底线。

### 题 8-7 [模拟题] "这个项目你踩过最大的坑是什么？"——复盘怎么讲？

**1. 问题与考查点**：失败叙事的结构与自我认知——"没坑"是零分答案，甩锅是负分答案。

**2. 常见错误回答**："没什么坑，挺顺利的。"——要么没做、要么没反思；或甩锅式复盘（"测试同学没测出来"）——暴露的是流程与格局问题。

**3. 简洁合格回答**：四段式：**现象**（可复现的表象）→**根因**（一句话说透机制）→**修复**（改动点）→**沉淀**（变成什么纪律/测试/监控）。本书提供三个"标准坑"模板（都是书中的真实实验案例——前提是你亲手复现过它们，才能讲成自己的实验）：
- **限流翻倍坑**：多实例部署后"60 次/分钟"变 120 次/分钟（计数器在进程内存）→根因：进程内状态在水平扩展后失真→修复：Redis INCR 外置→沉淀：状态外置清单进上线检查。
- **重试风暴坑**：下游抖动时退避无抖动，同毫秒集体重试把刚恢复的下游再打挂→根因：同步重试无随机化→修复：指数退避+抖动+预算上限→沉淀：重试参数模板化。
- **幻觉引用坑**：回答引用不存在的 [5]→根因：Prompt 约束是软的→修复：程序校验+回退抽取式→沉淀：引用有效性不变式测试。

**4. 深入解释**：好复盘的三个信号——根因到**机制层**（不说"配置错了"，要说"为什么这个配置会这样"）；沉淀**可复用**（变成测试/检查单/监控项，而不是"下次注意"）；诚实**分层**（我的失误/团队流程的洞/工具的坑，各归各位，不混着说）。复盘与题 4-8 的排障流程呼应：坑的"现象→根因"段就是一次排障。

**5. 工程案例**：三个坑分别对应 part03 ch19.1（多实例限流翻倍）、ch15.1（重试风暴）、part06 EX-34-02（幻觉引用）——全部有代码与测试可复现；面试前把自己项目里对应的真实坑也各写一个四段式。

**6. 追问与回答边界**：
- 追问 1："怎么保证不会再犯？"——要点：指认沉淀物（测试名/检查单项/监控项），不复述"我会更小心"。
- 追问 2："如果重来一次？"——要点：按**当时的信息面**重推决策，展示"决策-信息"关系而不是上帝视角。
- 边界：坑必须真实——教材的坑要先亲手复现再讲成自己的实验；绝不能讲成"公司生产事故"（那是编造经历）。

### 题 8-8 [模拟题] "你做了这么多年 Java，为什么转 AI 应用？用 Python 会不会可惜？"

**1. 问题与考查点**：动机真实性与身份稳定性——面试官在评估"拿了 offer 会不会走"与"是不是跟风"；同时暗中考你对两个生态的真实理解。

**2. 常见错误回答**："Java 太卷了/Python 火。"——动机外部化、随波逐流；或贬低 Java 抬高 Python——对面可能就是 Java 背景的面试官，还暴露你不懂"工程经验是资产"。

**3. 简洁合格回答**（三段式，按自己真实情况填空）：① **变化的事实**：我所在的业务开始长 AI 功能（举例：客服问答/日志排障），这类功能的主生态在 Python（模型 SDK、LangChain/LangGraph、评估工具链），我顺着手头需求系统学了一套面向 Java 开发者的课程并跑通了两个完整项目（指向具体项目）；② **经验的平移**：AI 应用的大头是普通工程——并发控制、超时重试、幂等、权限、评估回归，这些是我 Java 年限的直接资产，Python 只是把工具换了（Semaphore≈Bulkhead、评估集≈契约测试、checkpointer≈流程实例存储）；③ **职业判断**：我要做的是"AI 应用工程师"——应用工程向，不碰训练；Java 经验不是沉没成本，是这个方向上的差异化（不少 Python 出身的人反而缺服务工程深度）。

**4. 深入解释**：表达纪律：用**不承诺式**表述（"我的判断是应用层机会在增长"而不是"这行必然大火"）；被问"会不会回去写 Java"——答"集成场景里我本来就要写"（Python AI 服务 ↔ Spring Boot 的双向集成是常态），两栈是组合不是二选一。动机答案没有标准，只有**真实与具体**之分：能举出自己手头需求的动机 > 任何宏观叙事。

**5. 工程案例**：本书 ch01 的定位声明本身就是答案的理论版——"AI 应用工程师=把输出不可控的模型能力，用工程手段包装成行为可预期的服务；模型那部分你只能'选与防'，其余全部是普通工程活，而普通工程活正是 Java 老手的主场"。

**6. 追问与回答边界**：
- 追问 1："Python 哪里让你不爽？"——要点：给真实的具体点（GIL/打包/类型检查弱）+缓解手段（进程池/mypy/锁定依赖）——抱怨+方案=深度；只抱怨=浅。
- 追问 2："算法要不要补？"——要点：按第十一部分的边界答——会判断适用场景（RAG/Prompt/微调选择树），不装会训练；"应用工程师的算法知识边界"本身就是一个好答案。
- 边界：不贬低任一语言、不承诺行业判断；一切以你真实的经历与判断填空。

### 题 8-9 [模拟题] "你这个 100% 的评估指标是真的吗？"——数字被质疑怎么回应？

**1. 问题与考查点**：数字的**口径意识**——每个数字必须能说出"怎么来的、适用范围、谁可以复现"；同时考压力下的诚实（这是价值观题）。

**2. 常见错误回答**："测试都过了，就是真的。"——说不出口径；或慌忙把数字改小——一致性崩塌（题 8-6 的反面教材）；或反过来硬顶（"我的数字不会有错"）——暴露没有口径意识。

**3. 简洁合格回答**（三句话公式：**口径→条件→复现**）："这个 100% 是 16 条评估集上的四指标（hit@2/关键词覆盖/引用有效/拒答正确），评估集和语料是配套的合成资产；它的适用条件是 Mock 模式、这套语料、这套切分参数；复现命令是 `python3 eval/run_eval.py`，任何人跑一遍都能验证。它的含义是'结构回归守门'，不是语义质量证明——README 里明确写了'答案是否真对要人工抽检'。"三原则：不引用没跑过的数字；数字与版本绑定（切分/模型/Prompt 三元组）；口径升级主动声明（"换真实 embedding 这些数字全部要重校"）。

**4. 深入解释**：面试官质疑数字多半在测"你知不知道它的脆弱性"——**主动说出局限（样本量小、合成语料、Mock 模型）比被戳穿体面得多**；这也是本书写作红线的面试版：不把没实测的东西说成实测（FACTS 红线 4）。压力测试的终极题："那你给个真实准确率？"——标准答案："在没有可靠口径之前我不给数字；方法上是评估集+人工抽检双门槛，建起来之前我不承诺。"——拒给数字但给路径，是这一题的满分形态。

**5. 工程案例**：P1 README 第 6 节的指标口径段落（"词面级/结构级指标只能做回归守门"）与第 12 节未验证项清单——两处都是"数字带边界"的书面示范。

**6. 追问与回答边界**：
- 追问 1："怎么把指标做得更可信？"——要点：扩样本、真实模型夜间评估、badcase 回填、人工对齐 LLM 判官（算一致率）。
- 追问 2："你们公司（项目）的线上指标呢？"——要点：没有就说没有，说清"我讲的都是可复现的离线口径"。
- 边界：**永不为压力当场造数**——这是职业底线题，答案没有灰色地带。

### 题 8-10 [模拟题] 面试最后"你有什么想问的？"——反问什么既加分又拿信息？

**1. 问题与考查点**：判断力与职业成熟度——反问是双向面试的评分点，也是你唯一的信息采集窗口。

**2. 常见错误回答**："没有问题了。"——放弃窗口、显得没兴趣；或只问薪资加班（那是 HR 环节的题）；或问出"贵司用什么大模型"这类一查官网就知道的问题。

**3. 简洁合格回答**（按目的分组，选 2~3 个）：
- **判断技术成色**："团队现在怎么评估一个 AI 功能的效果？有没有固定的评估集或回归机制？"——没有评估体系的团队，AI 功能基本靠感觉迭代（这是你入职后最大的坑或最大的机会）。
- **判断工程位置**："AI 部分是独立服务还是嵌在业务服务里？和 Java 侧的集成模式是什么？"——直接决定你的工作形态（ch57 的分工视角）。
- **判断风险意识**："上一次 AI 相关的线上事故是怎么复盘的？"——有复盘文化 vs 甩锅文化的分水岭。
- **判断成长空间**："这个岗位负责的是从需求到评估的全链路，还是只做其中一段？"
- **收尾式表态**："如果我入职，前 30 天您期望我交付什么？"——把面试变成试用期预演。

**4. 深入解释**：反问的隐藏功能——**你提的问题就是你的能力画像**：问评估体系的人被默认懂评估，问复盘文化的人被默认经历过生产。听到答案后的追问（"评估集谁维护？""指标掉了我有权限回滚吗？"）进一步展示工程素养。反问答案本身也是决策输入：三个问题都答不上来的团队，你的 offer 决策要重新掂量。

**5. 工程案例**：本书 ch60（成本与可观测）与 ch61（上线清单）的问题化版本——把书里的清单变成反问，既自然又专业（"上线前你们过什么检查单？"）。

**6. 追问与回答边界**：
- 本题无追问，但注意：offer 判断与薪资谈判不在本书范围，**本书不承诺任何求职结果**——反问策略只提高信息质量，不保证结果。
