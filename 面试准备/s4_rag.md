## 12.4 专题四：RAG

> 对应正文：part05（ch26~ch28，Prompt/历史/注入）与 part06（ch30~ch36）、项目一（综合项目/项目一_文档知识库）。RAG 是 AI 应用岗出现频率最高的主题，也是对 Java 老手最"友好"的主题——检索、权限、评估、排障全是后端工程的主场。

### 题 4-1 [模拟题] 上下文窗口越来越长，为什么还要 RAG？什么时候不该用 RAG？

**1. 问题与考查点**：技术演进下的架构判断+"反向边界"——能说清"何时不该用"比背"是什么"高一个层级；顺带考你把幻觉、成本、权限三个维度分开谈的能力。

**2. 常见错误回答**："窗口小所以需要 RAG，窗口大了 RAG 就淘汰了。"——把 RAG 的价值押在窗口大小这一个变量上；或者说不出 RAG 自己的成本面（好像它是免费的）。

**3. 简洁合格回答**：窗口解决"塞得下"，RAG 解决三件窗口解决不了的事：① **成本**——全量知识每次请求重付 token，费用随知识量线性涨；② **权限**——按用户过滤必须在检索层做，塞窗口等于把全部文档发给每个用户；③ **时效与治理**——改文档即生效，索引可增量更新、可审计。反过来四种情况不该用：知识量小且稳定（几千 token 内，直接放 Prompt/长上下文）；要实时数据（走工具查询）；要改风格/格式（微调或 few-shot）；问题本质是"算"不是"查"（工具）。一句口诀收尾：**微调教"怎么做"，RAG 送"要知道什么"，工具查"现在是什么"**。

**4. 深入解释**：决策工具是"四连问"：知识会变吗、有多大、要按人隔离吗、答案要实时吗——两个以上"是"选 RAG，全"否"用长上下文/纯 Prompt，"查系统数据"用工具（见 ch30 的四方案对照表）。幻觉要拆三层谈：知识缺失型（RAG 直接对症）、上下文背离型（RAG 缓解，忠实性指标对症）、推理错误型（RAG 无能为力，工具对症）——"上了 RAG 就不会胡说"是本专题最典型的错误答案。RAG 的完整成本不止 token：一次性建设（清洗/切分调参/评估集）、检索延迟（embedding 在真实模式下是一次网络调用）、运维（同步/重建/坏例分析）、评估回归（每次换模型改参数都要重跑）。加分动作：现场用 EX-30-02 的 token 算术把两种方案的每日输入量算给面试官看。

**5. 工程案例**：见 part06 ch30——EX-30-01 三场景演示（编造的制度条款）、EX-30-02 决策表（长上下文 277 token/次 vs RAG top-3 187 token/次，日请求 1 万时差距放大且未计检索侧）；P1 的立项依据就是三条命中：制度会改、要按部门隔离、要拒答（综合项目/p1 README 第 1 节）。

**6. 追问与回答边界**：
- 追问 1：百万级窗口普及后 RAG 形态会怎么变？——要点：top-k 能给的块更多、切分可以更粗，但成本/权限/时效三条理由不变，检索层的地位反而更突出。
- 追问 2：RAG 和微调能混用吗？——要点：能且常见：微调管输出风格与格式服从，RAG 管事实供给；对应 ch62 的选择树。
- 边界：各模型窗口/价格变化快，本书刻意不写死任何真实模型数字——面试同样只给方法与算式，具体以厂商文档为准。

### 题 4-2 [模拟题] chunk_size 怎么定？切分有没有"最佳实践"？

**1. 问题与考查点**：反对背数字——考"参数是评估出来的"这条纪律，以及切分器机制（overlap 生效条件、结构与元数据）的理解深度。

**2. 常见错误回答**："业界最佳实践 512。""越大越好，塞的上下文多。"——报数字的人答不出数字从哪来；前者是把别人语料的校准值当普适真理，后者忽略"一块混多主题、向量被稀释"的反向伤害。

**3. 简洁合格回答**：没有跨语料的万能值，只有方法：① 从"一条完整规则/一个语义单元"的典型长度定初值；② 理解两个参数各管什么——chunk_size 是检索单元粒度（太小→语义单元被劈开、单块命中残缺；太大→无关内容稀释向量、引用粒度粗），overlap 是边界容错（通常取 size 的 10%~20%，且只在"内容超过 size 需要续切"时生效）；③ 有结构信号的文档先按标题分节、再节内细切（两级管线），让"门牌号"变成元数据；④ 改参数必须重跑评估集看 hit@k 与端到端答案质量取交点，发布走"重建影子索引→评估对比→灰度切换"。

**4. 深入解释**：三个容易被追问的细节：① 字符 vs token 口径——默认 `length_function=len` 按字符数，token 口径管窗口预算、字符口径管 embedding 上限，中文含数字文本两者差异大；② 元数据在入库瞬间定死（溯源/权限/展示三类，必需字段缺失拒绝入库 fail fast）——"需要时再补"会让向量与元数据失同步；③ 表格三类做法（小表整块转 markdown、大表行级切分并复制表头、结构化数据抽字段走工具查询）——展平丢行列对应关系几乎必错；④ 中文必须显式传分隔符，默认分隔符面向英文，会退化到字符级硬切（ch41 实测）。

**5. 工程案例**：见 part06 ch32 三个 EX——EX-32-01（固定长度的"半句话"）、EX-32-02（递归切分与"5 字标题块"盲区）、EX-32-03（两级管线+元数据设计）；P1 的 200/30 是在 16 条评估集上试出来的（README 第 2 节选型表），不是 industry standard——这句话本身就是标准答案的一部分。

**6. 追问与回答边界**：
- 追问 1：语义切分（按 embedding 相似度找断点）好吗？——要点：工程顺序先结构、后句界、最后语义断点；语义切分入库要多算相似度且断点质量依赖模型，除非评估证明结构切分不够。
- 追问 2：为什么"5 字块"是问题？——要点：`##` 是门牌号，纯长度切分不认识它；两级管线把标题消费成"边界+元数据"。
- 边界：200/30、0.16 等数字只对本合成语料+MockEmbedder 有效，引用时说"示例值，须用自家语料重校"。

### 题 4-3 [模拟题] 为什么只有向量检索不够？混合检索怎么做？

**1. 问题与考查点**：两路检索的互补机制+融合的工程理由（RRF 为什么只用名次）——考"检索系统"而非"调了个 embedding API"。

**2. 常见错误回答**："向量检索是语义的，比关键词高级，直接用它就行。"——把两路说成替代关系；或答不出"两路分数直接加权相加"为什么是错的。

**3. 简洁合格回答**：两路各治一种失败：向量路管"意思接近"（同义改述、跨表述），BM25 管"词面精确"（工单号 K3、专有名词、罕见缩写——真实 embedding 对词表外的编号同样没有稳定语义）。融合用 RRF：把两路结果折算成"名次倒数"再累加（k=60 是平化常数），天然免疫两路的量纲差异（BM25 0~20+ 对余弦 −1~1），直接加权会让分数大的一方独裁。top-k 管上下文预算（塞几块）、阈值管"最像的也够不像"（该不该拒答）——两个不同的闸门，取值都来自评估集（k 用 hit@k 曲线找召回饱和点；阈值取应答分数下界与应拒分数上界之间的空隙）。

**4. 深入解释**：BM25 三个参数各管一件事：IDF 是灵魂（只在 1/6 文档出现的词得到高区分度，处处出现的"的"几乎不得分）；k1 让词频增益饱和；b 惩罚长文档。中文的地基是分词，且**入库与查询必须用同一个分词器**（两侧不一致是"BM25 全零分"的第一根因）。向量侧：入库前 L2 归一化让点积=余弦，分数才有跨记录可比性，阈值才有意义。生产形态是"两路+一融合+一重排"：企业里 BM25 路常常就是现成的 Elasticsearch（8.x 的 hybrid query 原生支持 BM25+kNN+rrf），**你不需要为 BM25 路新建任何基础设施**——这正是混合检索在企业落地便宜的原因。查询改写是增益项且会漂（改写是生成行为），必须进评估回归。

**5. 工程案例**：见 part06 ch33——EX-33-01（numpy 归一化点积，25 块微秒级）、EX-33-02（BM25 手写与"K3 实验"：精确词 BM25 赢）、EX-33-03（RRF 融合：同义改述向量赢）；P1 的词面重排 `fused = 0.5*cos + 0.5*lex` 是 MockEmbedder 词表外区分度不足时的补偿设计（README 第 2 节），真实 embedding 下权重要重校。

**6. 追问与回答边界**：
- 追问 1：数据到千万级怎么办？——要点：ANN 索引（HNSW/IVF）+向量库选型四问（规模/权限过滤下推/更新频率/运维），近似召回率要用 hit@k 验收，不能只看延迟。
- 追问 2：为什么不用"分数归一化后加权"？——要点：RRF 免调参、对分数分布漂移鲁棒；先拿 80 分，评估证明不够再升级加权/LTR。
- 边界：FAISS 本书沙箱未安装（ch33.A 声明）；ES hybrid query 的参数名以官方文档核实为准。

### 题 4-4 [模拟题] 重排（rerank）什么时候值得上？代价是什么？

**1. 问题与考查点**：成本-收益判断——资深岗用这题区分"堆组件的人"与"算账的人"。

**2. 常见错误回答**："重排一定提升精度，直接上最强模型。"——不计成本与位置；或"重排就是再算一遍余弦"。——混淆双塔与交叉编码器。

**3. 简洁合格回答**：当评估显示"**召回对但排序错**"占坏例大头时才值得。交叉编码器把查询与候选拼在一起打分，精度显著高于双塔（向量检索是各自编码再比相似度，交叉编码是逐对细读），但每条候选一次模型推理，延迟与成本按候选数线性涨。常见配置：双塔召回 top-50 → 重排取 top-5 进上下文；用评估集验证重排前后的 hit@1 与答案质量，**涨了才留**。

**4. 深入解释**：两个结构认知：双塔的向量可以离线预计算（查询侧只算一次），交叉编码必须在线逐对算——这是延迟差异的根源；重排治不了"召回就没有"（那是切分/embedding 问题，先分层定位再上重排）。工程位置：权限过滤要在重排之前（无权候选不值得花重排算力）；重排前后的 hit@1 差值进监控，作为"这个组件还值不值得在"的持续证据。重排不是只能用模型——P1 的词面重排就是"便宜版"，关键是它有评估数据支撑。

**5. 工程案例**：见 part06 33.11 追问 3 的配置口径；P1 README 第 2 节对词面重排"存在理由与真实模型下的撤回条件"的记录——一个组件带着它的退出条件上线，这是可以主动讲的设计成熟度信号。

**6. 追问与回答边界**：
- 追问 1：重排与查询改写先做哪个？——要点：按坏例归因分桶：问法不匹配（改写）vs 排序错（重排），评估集说了算。
- 追问 2：重排模型怎么选？——要点：给方法不给品牌——延迟预算、部署形态（API/自托管）、评估集实测收益；本书未实测任何具体 rerank 模型，以实测为准。
- 边界：交叉编码器精度优势是机制层结论；具体模型的具体收益数字必须来自你自己的评估集。

### 题 4-5 [模拟题] 引用怎么做才能"可溯源"？模型总忘写 [n] 怎么办？

**1. 问题与考查点**："引用是接口约定，不是模型自觉"——三层防线的设计；顺带考预算装箱与流式协议的细节一致性。

**2. 常见错误回答**："在 Prompt 里要求模型写引用就行。"——Prompt 是软约束，模型偶发幻觉引用（引一个不存在的 [5]）；上线评审时这叫"不可验收"。或者反过来"让模型输出整个 JSON 含 citations"，但 citations 仍由模型自由发挥、没有程序校验。

**3. 简洁合格回答**：三层：① **Prompt 层**——编号证据块+few-shot 示例+"只依据编号证据"约束（软）；② **程序校验**——回答中 `[n]` ⊆ 本次检索返回的编号集合，校验失败当场拦截并回退抽取式回答（硬，必做）；③ **架构层**——结构化输出让 answer 与 citations 分字段返回，citations 由程序从"实际使用的块"生成，不靠模型写编号。配套两条纪律：块编号必须稳定且在 Prompt、回答、citations 三处指向同一个块；预算装不下的块**整块丢弃**——截半块会让模型基于"不可结转被截成可结转"的残句作答，比没有证据更危险。

**4. 深入解释**：三个高频事故的机制：① citations 与回答不同源（异步/流式下两处 top_k 不一致）→ 不变式"回答中的标记 ⊆ citations 编号"必须做成测试（P1 的 `test_ask_answered_with_valid_citations`）；② 忠实性自动校验的盲区——数字锚点便宜有效（制度类语料核心事实几乎都带数字），但"无数字的事实篡改"（"需审批"说成"无需审批"）要 LLM 判官初筛+人工终审；③ 引用数据结构每个字段给谁用（index 给前端、doc_id/chunk_id 给溯源、score 给排障、snippet 给展示）——能按消费方讲字段，比背字段名高一档。

**5. 工程案例**：见 part06 ch34——EX-34-01（编号证据+预算装箱：预算 320 装 2 丢 3）、EX-34-02（幻觉引用拦截：回答引用不存在的 [5] → 程序接管回退抽取式）；P1 的 SSE 三事件协议先发 meta（引用先行，README 第 5 节），拒答路径只有 meta+done。

**6. 追问与回答边界**：
- 追问 1：引用校验失败率升高说明什么？——要点：Prompt 漂移或检索质量下降，先看坏例归因再动约束；监控该率本身就是答案。
- 追问 2：多轮对话里引用怎么带？——要点：引用绑定"本轮证据"；跨轮指代先做查询改写重新检索，不沿用上一轮编号。
- 边界：内容级忠实性的自动指标有盲区（EX-35-03 的假阳性/假阴性），人工抽检环节不可省。

### 题 4-6 [模拟题] 多租户 RAG 的权限过滤为什么必须在检索层？怎么落地？

**1. 问题与考查点**：安全架构的位置感——"三个不"；这是 Java 工程师经验平移最顺的一题，答好它等于展示了"权限系统老手"的身份。

**2. 常见错误回答**："检索完把没权限的从结果里删掉就行。"——事后过滤泄露存在性（从"证据不足"与响应差异可推断被删内容的存在）、浪费召回名额（无权文档挤占 top-k），更糟的情况是内容已经进过模型上下文——输出过滤为时已晚。

**3. 简洁合格回答**：三个"不"：无权文档**不参与排序**（否则挤占召回名额）、**不进上下文**（进了就等于模型看过）、**不出现在引用里**（不泄露存在性）。落地：权限字段（tenant_id/department）是 chunk 元数据的一部分、入库时定死；过滤发生在打分函数**入口**（候选集先过滤再算相似度）；生产把过滤下推到向量库/ES 的 metadata filter（避免拉全量，且"过滤后 top-k"的召回名额不被无权文档挤占）。身份只来自请求上下文（JWT/Session），**绝不来自问题文本或模型输出**——ch28 红线在 RAG 场景的落点。

**4. 深入解释**：与 Java 经验的精确对照：检索前 ACL ≈ SQL 的 `WHERE tenant_id = ?`（参数化、在查询层），而不是查出来再在应用层删——你写过的每一行行级权限代码都是这里的经验。权限模型设计：部门继承等规则放权限模块，检索模块只消费"一个集合"的抽象（职责分离，改继承不动检索）。fail-closed：过滤逻辑异常时宁可全拒不可全放——权限组件是安全闸不是可用性闸。测试要锁"无权用户的检索结果里不存在该文档"（存在性测试），不只是"返回为空"。

**5. 工程案例**：见 part06 ch34 EX-34-03（mallory 视角里 acme 文档"不存在"——与"查无此文"体验一致，没有"存在但无权"的暗示）；P1 的 can_read 是 kb.py 检索第一步（README 第 2 节架构图），finance 用户问年假得到 `refused` 而非权限暗示（第 5 节失败路径表）；测试/test_p1.py 的租户隔离与部门 ACL 用例。

**6. 追问与回答边界**：
- 追问 1：权限过滤与向量库 filter 什么关系？——要点：教学实现内存过滤（25 块无所谓），生产必须下推；"过滤下推能力"是向量库核心选型指标之一。
- 追问 2：文档权限变了但向量没重嵌入，怎么办？——要点：权限在元数据不在向量里，更新元数据即可；若切分边界依赖密级（按章节密级分块），才需要重建。
- 边界：数据库行级安全（RLS）与向量库组合的细节随产品而异，以所用组件文档为准；本书沙箱未接真实 RBAC 系统。

### 题 4-7 [模拟题] RAG 的效果怎么评估？hit@k、忠实性这些指标怎么落地？

**1. 问题与考查点**：把"好不好"变成可计算数字——这是 AI 应用岗与"调 API 玩票"的分水岭，也是 ch35 的验收标准。

**2. 常见错误回答**："人工看几条，感觉还行。"或"用 GPT 打个分。"——没有可计算定义就没有回归：改任何参数（切分/阈值/模型/Prompt）都在裸奔，"感觉变好"不是工程。

**3. 简洁合格回答**：评估集先行：20~50 条起步，**应答与应拒答两类用例都要有**，每条带期望（期望命中文档/关键词/拒答标记）。四类可计算指标：① 检索层 **hit@k 与 MRR**——hit 管"正确文档进没进前 k"（用户可见性），MRR 管"平均排第几"（排序敏感度），hit 平稳而 MRR 下滑说明排序在退化，两个一起看互当校验；② **忠实性代理**——数字锚点（回答中的数字必须出现在被引块里，制度类语料的便宜兜底）；③ **引用正确性**——回答中 `[n]` ⊆ citations；④ **拒答正确率**——该拒的拒、不该拒的不误伤（误拒与漏拒是一对跷跷板）。指标进 pytest 做 CI 回归；LLM-as-judge 只做规模化初筛，判官要定期与人工判读对齐一致率。

**4. 深入解释**：自动评估的两大局限要有名字：**假阳性**（词面全中但张冠李戴——自动通过人工不通过）处置是补指标（引用-句子对齐）；**假阴性**（正确转述换词——自动拦截人工通过）处置是放宽指标或补同义词。评估集纪律：与被测系统独立评审（不许"顺手改期望"）、badcase 脱敏回填、与版本三元组（切分/模型/Prompt）绑定——任何一元变更都能解释指标变化。上线门槛是"自动指标+人工抽检"双门槛：自动全绿只说明已知风险守住了，不等于线上没问题（分布外用例）。

**5. 工程案例**：见 part06 ch35 三个 EX（EX-35-01 hit@2=100% 而 MRR=0.833 的互补实证、EX-35-02 四种失败形态与数字锚点、EX-35-03 假阳/假阴）；P1 的 16 条评估集四指标 100%（README 第 6 节），并且主动声明"词面级/结构级指标只能做回归守门，答案是否真对要人工抽检"——这句诚实声明在面试里本身就是加分项。

**6. 追问与回答边界**：
- 追问 1：评估集多少条够？——要点：看覆盖度不看条数：高频问题全覆盖、每类失败形态至少 1 条、badcase 全回填；做"两种 embedding 谁好"级别的比较要百条级并关注波动。
- 追问 2：评估全绿但用户说答错了？——要点：分布外——脱敏回填先复现失败；复现不了说明缺多轮/会话上下文维度（ch27）。
- 边界：LLM 判官的一致率因模型与任务而异，本书未实测真实判官——给机制与对齐方法，不给数字。

### 题 4-8 [模拟题] 用户反馈"RAG 答错了"，你的排障路径是什么？

**1. 问题与考查点**：分层排障方法论——第六部分的验收标准（"给出至少 3 类定位手段"），也是把前面 7 题串成流程的收口题。

**2. 常见错误回答**："先调 Prompt。"或"换个更强的模型。"——不分层瞎调，改完没有评估佐证，同类错误下周照来；更糟的是"每次都改 Prompt"会把本来是检索问题的坏例越调越坏。

**3. 简洁合格回答**：三步定位：① **分层复算**——单独跑检索层算 hit@k（不看生成）：没中→检索问题（文档没入库/切分切碎/索引过期/问法不匹配）；中了再看生成层（忠实性/引用校验）：命中还错→Prompt 约束或模型问题；② **看分数分布**——top-k 分数整体偏低说明语料-模型不匹配或阈值过松；应答与应拒用例的分数区间重叠说明阈值没分开（重校）；③ **拒答原因分桶**——`no_relevant_evidence` 多=知识缺口（补文档）、`below_score_threshold` 多=问法不匹配（查询改写/同义词表）、`evidence_insufficient_judge` 多=召回内容跑题（切分粒度/embedding 质量）。修复后重跑评估集证明有效，再灰度上线。

**4. 深入解释**：能把排障做成"三桶分流"的前提是**结构化 refusal_reason**——这就是为什么拒答原因必须是枚举三态而不是一段话（ch34 的设计动机）。hit@k 突降但没人改代码时，先分三类漂移再动手：数据漂移（语料变了）/配置漂移（阈值过滤变了）/基准漂移（评估集被改）。还有一类"检索和生成都没错但用户不满意"——问法/粒度问题，评估集补样本、考虑查询改写。会话类问题（多轮指代）不在单轮评估覆盖内，要单独补维度（ch27）。

**5. 工程案例**：P1 的排障流程已经写进面试讲法（README 第 10 节原话："先看 refusal_reason 分流，再看 top-k 分数分布判断是检索问题还是生成问题"）；两道闸各拦住过不同坏例的实证——跨租户查询靠余弦分数越过 gate1、被 gate2 词面判定拦下（run log 有记录，README 第 5 节）；ch30 调试题参考答案给出"年假可以结转"错答的三类原因定位。

**6. 追问与回答边界**：
- 追问 1：怎么防止同类错误复发？——要点：badcase 脱敏回填评估集 + 原因码统计驱动改进排序（哪类原因多先修哪类）。
- 追问 2：定位手段的前提是什么？——要点：可观测——citations、refusal_reason、分数都要落日志（"可回放模型当时看到了什么"），没有留痕就没有排障。
- 边界：阈值/权重数字只对本书合成语料有效；"答错"的最终判据要人工定义，自动化只能守结构与回归。

### 专题四 · 30 分钟自测（模拟口试）

> 用法：同前。本专题评分重点：决策题要"给出判据"，机制题要"给出版本/位置"，数字题要"给出处"。

1. **[模拟题] 用四连问法现场分析"公司价值观手册问答"该不该上 RAG。** 评分要点——30 页约几千 token、年更、全员可见、无实时要求→四问全否→长上下文或纯 Prompt；能补 RAG 成本结构至少两项（建设/延迟/运维/评估）加分。
2. **[模拟题] top-k 和阈值是两道什么闸门？取值怎么定？** 评分要点——top-k 管上下文预算、阈值管"该不该拒答"；k 用 hit@k 曲线找召回饱和点，阈值取应答/应拒分数分布的空隙；说"都是评估出来的，不是拍的"。
3. **[模拟题] 口头推导：RRF 为什么只用名次不用原始分？** 评分要点——两路量纲不同（BM25 0~20+ vs 余弦 −1~1）；对分数分布漂移鲁棒、免调参；代价是丢"分数置信度"；能补"加权归一化是升级路线，评估证明不够再上"加分。
4. **[模拟题] 拒答双保险各拦什么？举一个 gate1 放行但 gate2 拦下的例子。** 评分要点——gate1 拦"检索器不自信"、gate2 拦"自信的跑题"；P1 跨租户案例（词面撞上文档分数过 0.16、词面重合不足被拦）；判定器失效 fail-closed。
5. **[模拟题] 白板画出"RAG 答错"的三步排障流程。** 评分要点——分层复算（hit@k 分清检索/生成）→分数分布（阈值两侧是否分开）→拒答原因分桶（知识缺口/问法/召回跑题）；修复后必须重跑评估+灰度。
